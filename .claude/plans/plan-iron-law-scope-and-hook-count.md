## Task A — the hook count

### Evidence (measured, not assumed)

`scripts/gen-docs.py:55` globs `*.sh` and excludes `lib.sh` as "a sourced helper library,
not a hook". Applying that same rule honestly to the new Python files:

| file | verdict | evidence |
|------|---------|----------|
| `reflection-gate.py` | **is a hook** | referenced 7× in `.claude/settings.json` (PreToolUse, PostToolUse, SessionStart, PreCompact, Stop, SubagentStop, PostToolUseFailure) |
| `reflection.py` | **is NOT a hook** | never referenced in `settings.json`; `reflection-gate.py:67` does `import reflection`. It is a library + CLI, exactly like `lib.sh`. |

**So the true count is 20, not 21.** The briefing's "21" counts `reflection.py`, which
would be inconsistent with excluding `lib.sh`. Measured: 19 shell hooks (incl.
`post-implement.sh`, which is wired via the deprecated `config.json`, not `settings.json`)
+ `reflection-gate.py` = **20**.

### Step 1 — `scripts/gen-docs.py`: count Python hooks

- **File:** `scripts/gen-docs.py` · **Action:** Modify
- Replace `count_hooks()` with `_hook_files()` (globs `*.sh` **and** `*.py`) plus
  `_is_helper_module(path, siblings)`, which returns True when *another* hook file
  sources (`. …/lib.sh`) or imports (`import reflection`) the candidate.
- **Why structural, not a name list:** `{"lib.sh", "reflection.py"}` hard-coded would rot
  the next time a helper is added — the same class of bug we are fixing. Detection by
  "someone else loads this file" drops both automatically and needs no future edit.

### Step 2 — `scripts/gen-docs.py`: let the generator own prose counts

- Three prose sites hard-code `19`: `README.md:264`, `README.md:343` (inside a fenced
  tree diagram), `docs/HOOKS.md:3`. `scan_drift()` already *detects* them (CI fails), but
  write-mode only printed "fix manually" — which invites a human to hand-edit a count.
- Add `fix_drift(c)` + `_fix_line()`: in write mode, rewrite only the matched number,
  preserving the rest of the line; then re-scan and return 1 if anything is left.
- Add `IGNORE_MARKER = "gen-docs:ignore"`, honoured by both `scan_drift` and `fix_drift`,
  so a genuine example (`"add 2 hooks of your own"`) can opt out.
- **Nothing else consumes the count:** `tests/test_shell_lint.py:23` globs `*.sh` and
  **must keep doing so** (shellcheck cannot lint Python) — unchanged. `ck doctor`
  (`src/claudekit/cli/main.py`) checks agents/commands/skills, never hooks. No test
  asserts a literal hook number.

### Out-of-scope finding (report only — file not mine)

`install.sh:245-247` copies `hooks/*.sh`, `*.json`, `*.md` — **not `*.py`**. Installed
user projects therefore get `settings.json` entries pointing at `reflection-gate.py`
files that were never copied. That is a real shipping defect, but `install.sh` is outside
this workstream's ownership. Recommend a follow-up: add `cp "$CLAUDE_SRC"/hooks/*.py`
and count `*.py` in `HOOK_COUNT` (`install.sh:253`).

## Task B — repo-local Iron Law scope (Decision 21, Option A)

### The opt-in mechanism: a tracked root file `.ops-source-globs`

Weighed against the alternatives:

| option | travels with a fresh clone | explicit/greppable | leaks into user projects |
|---|---|---|---|
| `ECC_OPS_SOURCE_GLOBS` in `settings.local.json` | **no** (gitignored, per-dev) | yes | no |
| key in `.claude/hooks/config.json` | yes | yes | **yes** — `install.sh:246` copies `hooks/*.json` into every install |
| sentinel-sniffing (`src/claudekit/` + executor present) | yes | **no** (implicit; false-positives on forks/vendored copies) | possible |
| **tracked `/.ops-source-globs`** | **yes** | **yes** | **no** — nothing copies root dotfiles into an install |

Chosen: **`.ops-source-globs` at the repo root**, newline-separated shell case-globs
against the repo-relative path, `#` comments allowed. Verified not gitignored.
`ECC_OPS_SOURCE_GLOBS` (colon-separated) is kept as a precedence-taking escape hatch for
tests and one-off experiments; unset by default, so it cannot affect an ordinary install.

Contents (deliberately narrow — the product corpus only):
`.claude/agents/*`, `.claude/commands/*`, `.claude/skills/*`, `.claude/hooks/*`,
`.claude/operations/*`. (`*` in a shell `case` glob spans `/`, so subdirectories are covered.)
`.claude/settings.json` is **not** claimed — it is owner-gated configuration this
workstream does not own.

### Step 3 — `.ops-source-globs` (new, tracked)

- **File:** `.ops-source-globs` · **Action:** Create
- Header comment states the rule and the prohibition: never list `plans/`, `reports/`,

### Step 4 — `.claude/hooks/ops-enforcement.sh`

- **File:** `.claude/hooks/ops-enforcement.sh` · **Action:** Modify (3 edits)
- **Edit 1** (after the OS-scratchpad `case`, current `:42-44`): compute
  `OPS_SOURCE_MATCH`. Reads `ECC_OPS_SOURCE_GLOBS` else `$ABS_ROOT/.ops-source-globs`;
  if neither exists, `OPS_SOURCE_PATTERNS` is empty and **not a single subsequent line of
  behavior changes**. A hard-coded never-source denylist is checked *before* the globs:
  `.claude/plans/*`, `.claude/reports/*`, `.claude/knowledge/*`, `.claude/backups/*`,
  `.claude/settings.local.json`, `*.log`, `*.tmp`, `.claude/hooks/compact-counter.txt`,
  plus any target outside the repo root (`/*` after prefix-stripping). This denylist is
  belt-and-braces: even a maintainer who writes `.claude/*` into the marker cannot
  deadlock the repo. Pattern loop uses `set -f` + `IFS=$'\n'` so globs are not
  path-expanded — bash 3.2 safe, `shellcheck -S error` clean.
- **Edit 2** (current `:46-50`): wrap the `.claude/` and `*.md|txt|rst|adoc` exemptions in
  `if [ "$OPS_SOURCE_MATCH" -eq 0 ]`. The ops-config exemption (`:52-53`) and the
  executor-absent exemption (`:55-56`) stay **unconditional**, so `*.ops.json` is always
  writable and non-ops projects are untouched.
- **Edit 3** (before the final `deny`): a distinct denial message naming the override, so
  the failure is self-explaining and the test can assert on it.
- **Untouched:** the `:13` `minimal` short-circuit, `resolve_root`, fail-closed parsing,
  the cross-project block.

### Dormancy under `minimal` is intended, not an oversight

This repo's gitignored `settings.local.json` sets `ECC_HOOK_PROFILE=minimal`, under which
`ops-enforcement.sh` exits at `:13` before any of this code runs. **The override is
therefore dormant today by design.** Decision 21 is explicit that flipping the profile
default is the real velocity cost and the owner's call; this workstream ships only the
mechanism, which engages the moment the profile is anything but `minimal`. A test pins
that dormancy so it is documented behavior rather than an accident.

### Bootstrapping proof (the loop terminates)

1. Maintainer wants to edit `.claude/agents/planner.md` → `Edit` is blocked (exit 2) with
   the override message.
2. They author `.claude/plans/plan-x.ops.json` — `.claude/plans/*` is on the never-source
   denylist **and** matches `OPS_REGEX`, so `Write` succeeds. (Two independent reasons.)
3. `validate-config-json.py` then `execute-json-ops.py` apply the change. The engine
   writes files with Python I/O, not the `Edit` tool, so the PreToolUse hook never fires
   on the payload it applies.
4. Backups (`.claude/backups/*`), review records (`.claude/reports/*`) and knowledge
   (`.claude/knowledge/*`) are all denylisted → the engine can always write its own
   bookkeeping. **No step in the loop is blocked.**
5. Escape hatches if the hook itself is broken: `ECC_HOOK_PROFILE=minimal`, or
   `rm .ops-source-globs` (a Bash op, not an `Edit`).

### Step 5 — `tests/test_ops_enforcement_scope.py` (new)

Behavioral only: real `bash` runs of the real hook, real JSON on stdin, asserting exit
codes and stderr. `ECC_HOOK_PROFILE` forced on every run. Two throwaway git projects are
built per module — one with the repo's *actual* `.ops-source-globs`, one plain user
project. **Temp dirs are created beside the repo, never under `$TMPDIR`**: on macOS
`tempfile` returns `/var/folders/...`, which the hook exempts as OS scratch, and every
assertion would pass vacuously.

Matrix covered (50 tests): profile `minimal` vs `standard` × opted-in vs plain user
project × path class {product asset, workflow artifact, doc outside `.claude/`, ordinary
source, OS scratchpad, malformed payload, env-var opt-in} + the `.ops-source-globs`
manifest itself + hook-count assertions.

`test_denylist_beats_an_over_broad_glob` binds the never-source denylist ARM itself by
forcing `ECC_OPS_SOURCE_GLOBS=".claude/*"` and `"*"`: under the shipped marker those paths
match no glob, so without this test the whole arm could be deleted unnoticed. A companion
test proves the denylist is not a blanket allow (`src/` and agents stay blocked).

Marker robustness is covered too: a CRLF marker still enforces (`tr -d '\r'`), and an
unreadable marker fails dormant with an empty stderr (`cat ... 2>/dev/null`).

## Risk Assessment

- **Low:** `gen-docs.py` count change (verified end-to-end; no other consumer).
  Prose auto-fix (`IGNORE_MARKER` escape hatch; only the matched digits are replaced).
  Marker file addition (no test enumerates root files).
- **Low/Medium:** user-project regression. Mitigated structurally — with no marker and no
  env var, `OPS_SOURCE_PATTERNS` is empty and every branch is skipped — and empirically by
  6 parametrized user-project tests plus the fail-closed test.
- **Medium:** over-broad globs could deadlock maintainer workflow. Mitigated by the
  hard-coded never-source denylist evaluated *before* the globs, by the manifest test that
  rejects `plans|reports|knowledge|backups` in the marker, and by the bootstrapping proof.
- **Medium (accepted, owner-gated):** the override is inert while `ECC_HOOK_PROFILE=minimal`
  remains this repo's default. Shipping the mechanism now is deliberate.
- **Not addressed here (reported):** `install.sh` does not copy `*.py` hooks.
