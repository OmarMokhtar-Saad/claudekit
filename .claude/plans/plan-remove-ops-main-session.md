## 1. Goal and non-goals

Goal: after an approved `plan.md`, the **main session edits files directly** (Edit/Write). No `ops.json`, no `execute-json-ops.py`, no `implementer` agent. Subagents explore, review, test and verify; they never implement.

Non-goals: changing review thresholds (reviewer 90/100, verifier 80/100); touching `qa-agent-pro` or unmanaged repos (see fleet-layout); redesigning hooks unrelated to ops.

## 2. New flow

1. Plan: main session writes `plan.md` (planner agent only for large work, `/plan --deep`).
2. Review: `reviewer` scores plan.md (Plan 40 / Arch 30 / Security 30, >= 90). "No ops.json = AUTO-REJECT" is dropped.
3. Approval: user approves; `review-record.py` records APPROVED keyed on plan.md bytes (drift detection kept).
4. Implement: main session takes a git checkpoint (`auto-checkpoint.sh` / `/checkpoint`), then edits directly.
5. Verify: `verifier` + `tester`, `code-reviewer` on the diff.
6. Rollback: git/checkpoint based (`/rollback` rewritten).

Tiers: T1 direct edit, no plan. T2 plan by main session, no reviewer. T3 plan, reviewer, approval, main-session edit.

## 3. Safety properties that must survive (audit finding)

| Lost with ops engine | Replacement |
|---|---|
| Backup + transactional rollback (execute-json-ops.py) | checkpoint before edit + `/rollback` over git; `restore-backup.py` kept for backup manifests |
| Approval gate (review-record) | keep `review-record.py`, re-key to plan.md |
| Source-edit gate (ops-enforcement.sh) | NEW `plan-gate.sh` (section 3a): T3 edits blocked unless an approved, unchanged plan names the file; allow-list: docs, scratchpad, plan files, cross-project block kept |
| Execution lock | `concurrency-guard.py` partial; accept the gap, state it in docs |
| Baseline stamp | dropped (document) |
| "implementer never gets Edit" Iron Law | replaced by plan gate + golden-rule |

### 3a. Plan gate design (round 4: HMAC dropped, honest speed bump)
